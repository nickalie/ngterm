# AUR: the ngterm-bin package

## Overview

- Split from `docs/plans/completed/20261105-release-signing.md` (user, 2026-11-07). That plan publishes the GitHub
  release with the Linux tarballs, `SHA256SUMS` and its minisign signature. This plan puts ngterm in the Arch User
  Repository as
  `ngterm-bin`, built from those tarballs, and keeps it current with every release.
- Built on the release plan's job graph (`publish`, `publishing`, the `release` environment and its approval). It
  needs a published release to test against, so it starts after that plan's first real release (a rehearsal's
  tarballs serve for local tests before then).
- Credentials are requested as their task lands, one step at a time, with passwords and keys asked through zenity
  dialogs piped straight into the private keys repository's scripts (`./add.sh`, `./bitwarden.sh push`,
  `./sync.sh`); never through the chat.

## Context (from discovery)

- The release ships `ngterm-<version>-linux-{x86_64,aarch64}.tar.gz`; Linux archives start through `ngterm/AppRun`.
  The tarball carries the self-update marker `usr/share/ngterm/update-format` (`linux-archive`); the native packages
  drop it (`scripts/package-release.sh`), so package-manager installs never self-update.
- `packaging/linux/runtime-libraries.txt` lists the host libraries the build links against;
  `packaging/linux/nfpm.yaml` declares the native packages' dependencies (a Vulkan driver, `bubblewrap`,
  `xdg-dbus-proxy`, the desktop libraries).
- `packaging/linux/com.nickalie.ngterm.desktop` and the icons are in the tarball's `share`.
- The keys repository already lists `AUR_SSH_PRIVATE_KEY` (environment `release`).

## Development Approach

- As the release plan's: regular testing approach, tests in the same task, all checks green before the next task,
  this file kept in sync with the work.
- Checks are sized to the change (AGENTS.md > Choosing checks): no CI dry runs; `scripts/lint.sh` and the script's
  self-test; the package itself is checked by building and installing it locally (CachyOS, an Arch derivative).

## Implementation Steps

### Task 1: The PKGBUILD and its renderer

**Files:**
- Create: `packaging/linux/aur/PKGBUILD.in`, `scripts/aur.py` (with `--self-test`)
- Modify: `scripts/lint.sh` if the self-test needs wiring

- [ ] `ngterm-bin`: x86_64 and aarch64 sources from the release's Linux tarballs, the digests from `SHA256SUMS`,
      `provides`/`conflicts` `ngterm`, depends matching `packaging/linux/runtime-libraries.txt` and `nfpm.yaml`, the
      desktop file and icon, the license, the four commands on `PATH` from `/opt/ngterm`
- [ ] the PKGBUILD removes `usr/share/ngterm/update-format` from the unpacked tree, as `scripts/package-release.sh`
      does for the native packages: the tarball's `linux-archive` marker would make the updater treat a pacman-owned
      `/opt/ngterm` as a self-updating archive and fail on every release
- [ ] `aur.py` renders `PKGBUILD` and `.SRCINFO`'s inputs from the version and `SHA256SUMS`; its self-test pins the
      output
- [ ] tests: `scripts/lint.sh`; `makepkg -si` of the rendered package locally with a rehearsal's or release's tarball,
      `namcap` clean, ngterm starts from the installed package, and its update check says to update through the
      package manager
- [ ] run checks; must pass before Task 2

### Task 2: The aur job

**Files:**
- Modify: `.github/workflows/release.yml`

- [ ] job `aur` (publishing only, after `publish`, `environment: release`): renders `PKGBUILD` and `.SRCINFO`
      (`makepkg --printsrcinfo` in an `archlinux` container), checks with `namcap`, builds it once with `makepkg`,
      and pushes to `ssh://aur@aur.archlinux.org/ngterm-bin.git` with the deploy key (written to a 0600 file removed
      on exit, the AUR's host key pinned in the job)
- [ ] the job never runs on a rehearsal or a dry run; without `AUR_SSH_PRIVATE_KEY` it skips with a notice
      (`optional` mode) or fails (`required` mode)
- [ ] tests: `scripts/lint.sh`
- [ ] run checks; must pass before Task 3

**Credentials** (one step at a time): an AUR account (aur.archlinux.org); an SSH key pair generated here
(`ssh-keygen -t ed25519 -N "" -f aur`), the private key stored with `add.sh AUR_SSH_PRIVATE_KEY`, mirrored to
Bitwarden and synced, the public key shown to the user to add to the AUR account. The first push creates the package.

### Task 3: [Final] Verify and document

- [ ] grep check: `aur` runs only when `publishing`, never on a rehearsal
- [ ] `docs/release-signing.md`, an AUR section: the account, the key and its rotation; README: installing from the
