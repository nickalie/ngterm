# iOS app: a native remote-only ngterm for iPhone and iPad

## Overview

A native iOS app that views and drives the live sessions of remote ngterm machines (`ngterm-headless` on a server,
or a desktop instance), with the same v1 scope as the Android app in `mobile/android`.

- **What it does:**
  - add a machine, list its sessions, and create, end and attach them;
  - show the panes, the 1–2 pane split, agent status, context, HUD and notifications;
  - answer asks.
- **What it doesn't:** it runs no local sessions.
- **Rust:** a second frontend over `crates/ngterm-mobile`, exposed to Swift through UniFFI.
  - `ngterm-mobile` gets no iOS-specific code.
  - The libghostty-vt build gains the two iOS targets.
  - The only behavior change in the core is a fix that both apps need (Task 14: `suspend()` flushes a just-sent ask
    answer).
- **Swift:** SwiftUI over local Swift packages, with a UIKit terminal view hosted in SwiftUI.
- **Standards:** it follows Apple's Human Interface Guidelines and current iOS practice:
  - Swift 6 strict concurrency;
  - a strict lint gate from the first commit;
  - unit, snapshot and UI tests;
  - App Store readiness.
- **Conformance:** upstream has no mobile app, so this plan claims no conformance ids.

Decisions from the brainstorm and the plan review (2026-11-03, validated with the user):

- **Background: foreground-only v1, no APNs.**
  - iOS can't keep the ssh links up, so Android's `LinkService` (a foreground service with its Detach all
    notification) deliberately has no iOS counterpart.
  - When the whole app leaves the foreground, it keeps a short grace (`beginBackgroundTask`), then calls
    `suspend()`. Back in the foreground it calls `resume()`.
- **Asks live only while connected.**
  - In the foreground, or inside the grace, an ask shows as a sheet or as a notification with answer actions.
  - At `suspend()` the origin takes its asks back, as upstream does when a presenter goes away (`take_back_remote_ask`:
    a terminal ask is drawn on the origin, a GUI ask moves to its window or ends `presentation-lost`). The app
    withdraws their notifications then.
  - The origin's ask handoff is unchanged.
- **Background App Refresh: statuses only.**
  - It connects, lists each machine's sessions, and notifies the agents that turned waiting (`blocked`) or done
    (`completed`) since the last seen status, then disconnects.
  - It never attaches, so it never takes the presenter role.
- **Distribution:** a paid Apple Developer account, with the App Store as the target. A tag-triggered CI job uploads
  to TestFlight; App Store submission stays a manual click.
- **Platforms:** minimum iOS 26, with iPhone and iPad first-class. Apple Silicon simulators only (no x86_64 simulator
  slice).
- **Design:** HIG-native with ngterm accents:
  - system navigation, lists, sheets and toolbars, Liquid Glass chrome, SF Pro and Dynamic Type;
  - copper as the tint, and verdigris for healthy;
  - the status glyph + color + word system carried over;
  - the terminal palettes and bundled mono fonts shared with Android.

  The app has its own `mobile/ios/DESIGN.md`, not a port of Android's Material system.
- **Structure:** a thin checked-in `mobile/ios/NgTerm.xcodeproj` (buildable folders) over local Swift packages, with no
  Tuist or XcodeGen.
- **iPad windows:** one window per session. Opening a session that already has a window focuses that window, since
  two views of one `Pane` would fight over its pty size.

## Context (from discovery)

- **`crates/ngterm-mobile`**, the shared core:
  - **Shape:** an actor thread with a current-thread tokio runtime and a `LocalSet`, over russh. It is reached through
    UniFFI's proc-macro form, and its seams are `EventSink`, `KeyVault` and `HostKeyStore`.
  - **Callbacks run on the actor thread while it waits** (`api.rs`, the seam docs). The Swift side must never hop
    synchronously to the main actor inside them.
  - **Lifecycle:**
    - `suspend()` (`actor.rs`) closes every connection and stops the presentation streams.
    - `resume()` reconnects. A stream that left `connected` dismisses its open asks (`presentation.rs`,
      `set_connection`), and the new snapshot carries no asks (`ngterm-core` `frames.rs`, `PresentationSnapshot`).
  - **Answers:** `answer_ask` is fire-and-forget. The actor queues the `ask.resolve` line to the link task, and a
    `suspend()` right after closes the connection before that line is written.
  - **Session list:** `list_sessions` returns `RemoteSession`s with each agent's `status`, color and shape, with no
    attach.
  - **Drawing:** a pane draws from the packed row buffer `NGRB` v1 (`src/rows.rs`), with the shared golden
    `tests/fixtures/rows-golden.bin`.
  - **Sign-in:** `MobileEvent::SignInRequested` (Tailscale SSH check mode) is part of parity.
  - **Android-only parts:**
    - `uniffi.toml` has only `[bindings.kotlin]`;
    - Android-only wording in the docs of `lib.rs`, `api.rs` (`KeyVault`), `rows.rs`, `src/bin/uniffi-bindgen.rs`,
      the `Cargo.toml` description and comments, and `uniffi.toml`'s header.
- **`crates/ngterm-core/src/remote/handoff.rs`:** `present_ask_remotely`, `take_back_remote_ask` and `presenter_lost`
  are upstream's ask handoff. This plan leaves them unchanged.
- **`mobile/android`**, the parity reference. The code is the truth; `docs/plans/completed/20261102-android-app.md`

  - `service/LinkService.kt` (and its `IdleKeeper`, which doesn't suspend while a machine waits for sign-in)
  - `ui/terminal/` (RowBufferReader, TerminalPainter, GlyphCache, TerminalDecorations, KeyMapping,
    TerminalInputConnection, TerminalInput, ExtraKeysRow, TerminalGestures, TerminalMouse, SelectionHandles,

## Linting (from the first commit of `mobile/ios`)

The tools are the standard ones, with every version pinned. There are no baselines, and no suppression without a
reason.

- **Compiler:**
  - Swift 6 language mode;
  - `SWIFT_STRICT_CONCURRENCY = complete`;
  - `SWIFT_TREAT_WARNINGS_AS_ERRORS = YES`;
  - packages use `swiftLanguageModes: [.v6]` and the toolchain's warnings-as-errors setting.
- **SwiftLint**, version pinned in `build/pins.env`, run with `--strict`:
  - every opt-in rule on, except those that contradict each other or swift-format (for example
    `explicit_type_interface` against `redundant_type_annotation`), each listed in `.swiftlint.yml` with a reason;
  - analyzer rules (`unused_declaration`, `unused_import`) run over the build log;
  - complexity limits (`cyclomatic_complexity`, `function_body_length`, `type_body_length`, `file_length`) in the
    spirit of `clippy.toml`.
- **Suppressions:**
  - `blanket_disable_command` is on;
  - a `build-ios.sh lint` check requires every `swiftlint:disable:next` to carry a reason on the same line.
- **Formatting:** `swift format lint --strict` (the toolchain's swift-format), with `.swift-format` as the single
  source of truth.
- **Excluded:** the generated bindings, from both SwiftLint and swift-format.
- **Rust:** the workspace's strict clippy and `cargo fmt`, as always.

## Solution Overview

```
iOS app (Swift, SwiftUI + UIKit terminal)       ngterm-mobile (Rust, UniFFI)                server
┌────────────────────────────────────┐ async   ┌──────────────────────────────┐ russh ┌──────────────────┐
│ NgtermFeatures: screens, models    │ calls / │ actor thread (tokio, LocalSet)│──────▶│ ngtermctl live   │
│ NgtermTerminal: TerminalView       │ AsyncSt.│  ├ Machine: one ssh conn     │ exec  │ ngterm-session   │
│ NgtermPlatform: Keychain, notif.,  │◀───────▶│  ├ presentation per session  │       │ ngterm-headless  │
│   network, lifecycle, BG refresh   │         │  └ Pane: stream + row buffer │       └──────────────────┘
│ NgtermCore: facade + fake + FFI    │         └──────────────────────────────┘
└────────────────────────────────────┘           NgtermCoreFFI.xcframework (staticlib, device + sim)
```

- **Packages** (`mobile/ios/Packages/`, each with its own tests):
  - **`NgtermCore`:**
    - the binary target over the generated XCFramework, and the generated Swift bindings;
    - a `Sendable` facade: async calls, an `AsyncStream<MobileEvent>` fed by the `EventSink` callback, and protocols
      that the app and the fake both implement;
    - the `NgtermCoreFakes` product (`FakeMobileCore`, `FakePane`, `RowBufferWriter`), mirroring the Kotlin test
      fixtures.
  - **`NgtermDesign`:** tokens, status, the terminal palettes, fonts, components, and the contrast check.
  - **`NgtermTerminal`:** `RowBufferReader`, the Core Text painter and glyph cache, `TerminalView` (UIKit), the key
    map, the input view, and the accessory bar.
  - **`NgtermPlatform`:** the Keychain `KeyVault` and `HostKeyStore`, the JSON stores, `NWPathMonitor`, notifications,
    lifecycle, and background refresh.
  - **`NgtermFeatures`:** the `AppGraph`, the event routers (mirroring Android's `data/`), and onboarding, machines,
    sessions, session, asks and settings.
- **App target:**
  - `NgtermApp`: scenes, the `AppGraph` in `@Environment`, and a `@UIApplicationDelegateAdaptor` that registers the
    background refresh at launch;
  - `Info.plist`, entitlements, the asset catalog with the icon, `PrivacyInfo.xcprivacy` and the test plans.
- **State:**
  - `@MainActor @Observable` models, with views that hold no logic.
  - The core's callbacks yield into one `AsyncStream` (never a synchronous hop to the main actor), which `@MainActor`
    routers consume.
- **Navigation:**
  - `NavigationSplitView` (Machines → Sessions → Session), which collapses to a stack in compact width.
  - Settings is a sheet, and Onboarding is a full-screen cover on first run.
  - iPad windows follow the one-window-per-session rule.
- **Lifecycle, app-level:** it counts all foreground scenes (Android's `Foreground` counts started activities), so one
  iPad window going to the background suspends nothing.
  - **Last scene leaves the foreground:**
    - `beginBackgroundTask`;
    - on expiry, withdraw the ask notifications and call `suspend()`;
    - at once if nothing is attached and no machine waits for sign-in (Android `IdleKeeper`'s exception).
  - **Back in the foreground:** `resume()`, and the core's reconnect reattaches.
  - **Sign-in links** open in an in-app `SFSafariViewController`, so the app stays in the foreground while the user
    signs in.
  - **Network:** `NWPathMonitor` calls `network_changed()`.
  - **Background App Refresh** (`BGAppRefreshTask`, `UIBackgroundModes: fetch`, `BGTaskSchedulerPermittedIdentifiers`):
    - runs only while the core is suspended or not yet started;
    - for each machine with attached sessions (the attached set is persisted, since iOS usually relaunches the process
      cold): connect, `list_sessions`, compare each status with the persisted baseline, notify a turn to
      waiting or done, disconnect;
    - leaves the suspended set as it was for the next `resume()`.
  - **Idle timer:** `isIdleTimerDisabled` while a session is on screen, if Settings allows it.
- **Secrets:**
  - Private keys live in the Keychain (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, so a refresh with the
    phone locked can still connect; never synchronizable). They are handed to Rust per connection, and Rust zeroizes
    them.
  - Host keys are pinned in the Keychain the same way.
  - The Secure Enclave can't hold Ed25519 keys, so it isn't used.

## Technical Details

- **Build (`scripts/build-ios.sh [--profile release|debug] [--no-xcode] [ACTION...]`):**
  1. Take the M2 lock: a per-user lock file, so only one `xcodebuild` runs at a time.
  2. `scripts/setup-ios.sh --check` (exports), then the libghostty-vt prefix (`scripts/build-ghostty-vt.sh`).
  3. `cargo rustc -p ngterm-mobile --lib --crate-type staticlib --target aarch64-apple-ios`, and the same for
     `aarch64-apple-ios-sim`.
     - The command-line crate type leaves `Cargo.toml` and the Android build unchanged.
     - The link flags come from `--print native-static-libs`.
  4. Generate the Swift bindings with the in-crate `uniffi-bindgen` in library mode, with `--language swift
     --no-format`, over the host build of the library.
  5. Stage the headers: the generated header, plus its module map renamed to `module.modulemap`, which clang requires
     inside an XCFramework's `Headers/`.
  6. `xcodebuild -create-xcframework` from the two archives.
  7. Write the outputs into `mobile/ios/Packages/NgtermCore/Generated/`, which is gitignored: SwiftPM paths can't leave
     the package root. Copy in the same way the shared inputs that live elsewhere: `rows-golden.bin` and the fonts
     from their one source.
  8. Run the actions:
     - `lint`: SwiftLint, swift-format, the analyzer rules and the reason check;
     - `build`;
     - `test` on the pinned iPhone and iPad simulators;
     - `archive`, unsigned unless the release environment is set.

  Everything `xcodebuild` and the tests launch runs with `NGTERM_*` stripped. `Package.swift` checks that
  `Generated/` exists and, if it doesn't, fails with a message that points to this script.
- **UniFFI Swift config:** `[bindings.swift]` in `crates/ngterm-mobile/uniffi.toml`:
  - `module_name = "NgtermCoreBindings"`;
  - `ffi_module_name = "NgtermCoreFFI"`;
  - `ffi_module_filename = "NgtermCoreFFI"`.

  UniFFI 0.32's templates already emit `Sendable` and `nonisolated(unsafe)`. Task 3 checks the output under Swift 6.
  If anything warns, the bindings target alone gets the narrowest setting that compiles it (with a reason in
  `Package.swift`), and the facade is the only thing that imports it.
- **Deployment target:**
  - `IPHONEOS_DEPLOYMENT_TARGET = "26.0"` goes in `.cargo/config.toml [env]`, next to `MACOSX_DEPLOYMENT_TARGET` and
    for the same reason: rustc's own iOS default would link an archive built for a newer iOS than the binary claims.
  - It joins `RERUN_ENV`.
  - `zig_build.rs` refuses anything below libghostty-vt's iOS floor (Ghostty's `Config.zig`).
- **Pins (`build/pins.env`):**
  - `IOS_XCODE_VERSION`
  - `IOS_SIMULATOR_RUNTIME`: one the `xcode-27` image ships (iOS 27.0), so CI downloads nothing; the goldens are
    recorded on it
  - `IOS_SIM_PHONE` and `IOS_SIM_TABLET` (device types)
  - `SWIFTLINT_VERSION` and `SWIFTLINT_SHA256` (the official `portable_swiftlint.zip` release)
- **Zig targets:** `aarch64-apple-ios` maps to `aarch64-ios.<ver>` and `aarch64-apple-ios-sim` to
  `aarch64-ios.<ver>-simulator`. The OS version goes on the OS part, and `simulator` is the ABI. This differs from the
  macOS form, which only appends the version.
- **Simulator test runner (`scripts/ios-sim-runner.sh`):**
  - set as `CARGO_TARGET_AARCH64_APPLE_IOS_SIM_RUNNER`;
  - boots the pinned simulator and runs the test binary through `xcrun simctl spawn`, passing its exit code through;
  - forwards `RUST_BACKTRACE` and `RUST_TEST_*` as `SIMCTL_CHILD_*`.
- **Events into Swift:**
  - The facade's `EventSink` yields into an `AsyncStream<MobileEvent>` with `.bufferingPolicy(.unbounded)`, since
    events are small and losing one is worse.
  - `PaneDirty` is coalesced per pane in the terminal: the next display-link tick pulls one `frame(since:)`.
- **Asks (Android's rule, within the connected window):**
  - An ask for any attached session shows as a sheet when that session is on screen. Otherwise, while the core is
    connected, it shows as a notification:
    - button asks become actions;
    - input asks become a text-input action;
    - choice asks open the app.
  - An action handled during the grace answers through the still-running core.
  - At suspend, every ask notification is withdrawn (`removeDeliveredNotifications`), since the origin has taken the
    asks back.
- **Status baseline:**
  - The routers persist the last status seen for each attached session.
  - A refresh notifies only a turn to `blocked` or `completed` against that baseline: snapshot statuses after a
    reconnect carry `changed: false`, so Android's `changed` rule alone would post nothing.
- **Release (`.github/workflows/ios-release.yml`):**
  - **Trigger:** the release tags `release.yml` uses, plus `workflow_dispatch` with a `dry_run` input.
  - **Signing:** automatic signing through an App Store Connect API key with the Admin role, from secrets
    (`-allowProvisioningUpdates -authenticationKeyPath/ID/IssuerID`). If cloud signing refuses, the fallback imports a
    distribution certificate into a temporary keychain.
  - **Archive and upload:** `xcodebuild archive`, then `-exportArchive` with `ExportOptions.plist`:
    - `method = app-store-connect`;
    - `destination = upload`, or `export` for a dry run;
    - `manageAppVersionAndBuildNumber = false`.
  - **Versions:** the marketing version is the workspace version, and the build number is the release tag's commit
    count.
